同じ内容を、GET と POST の方法でサーバに送ってみます。
※ (A)(B) はこのサイトのサーバに、(C) は外部のテスト用サーバに送ります。どれも個人情報は入れないでください。

(A) GET で送る

確かめよう

  • 送信したあと、アドレスバーの URL はどうなった？（? のうしろに注目）
  • Network タブで、Request Method と Status Code は？

(B) POST で送る

送信する前に予想してみよう

このサイトを置いている GitHub Pages は、置いてあるファイルを渡すだけのサーバです。
そこへ POST でデータを送ると、何が起きるでしょう？

予想の答えと理由を見る
  • 何が起きる？ エラーになります。ステータスコードは 405（Method Not Allowed）。画面には「このページは動作していません」などと表示されます。
  • なぜ？ POST は「このデータを受け取って、何か処理してください」という頼み方です。でも GitHub Pages には、送られたデータを受け取って処理するプログラムがありません。そこで「その送り方（メソッド）は受け付けていません」と断ります。
  • 見どころ： URL に ? は付きません。それでも Network タブで result.html の行の「Payload（ペイロード）」を開くと、送ったデータが入っています。データはちゃんと届いていて、サーバに断られただけです。

※ エラー画面が出たあとに再読み込みすると、もう一度送信するか確認されます。再読み込みはせず「戻る」で戻りましょう。

確かめよう

  • 送信したあと、URL に ? は付いた？
  • Status Code は何番？ その番号はどういう意味？
  • ヒント: このサイトを置いているサーバ（GitHub Pages）は、ファイルを渡すだけのサーバです
  • Network タブで result.html の行をクリックし、「Payload（ペイロード）」タブを開くと、送ったデータはどこに入っている？

(C) データを処理してくれるサーバに POST で送る

送り先を、受け取ったデータをそのまま返してくれるテスト用のサーバ（httpbin.org）にしたフォームです。

送信する前に予想してみよう

(B) と同じデータを、同じ POST で送ります。違うのは送り先のサーバだけです。
今度は何が起きるでしょう？

予想の答えと理由を見る
  • 何が起きる？ 成功します。ステータスコードは 200（OK）。画面には、送った内容が "form" の欄に入った文字の一覧（JSON という形式）が表示されます。
  • なぜ？ httpbin.org では、POST で送られたデータを受け取って処理するプログラムが動いています（ここでの処理は「受け取った内容をそのまま返す」こと）。
  • 見どころ： 同じデータ・同じ POST でも、(B) は 405、(C) は 200。結果は「受け取る側のサーバが、その頼み方に対応しているか」で決まります。

確かめよう

  • Status Code は何番？ (B) とはなぜ違う？
  • 返ってきた画面の "form" の部分に、送った内容が入っている？
  • httpbin.org が動いていないときは、予備のボタンを使う

注意：返ってきた画面の "origin" には、あなたのインターネット上の住所（IP アドレス）が表示されます。この画面を SNS に載せたり、人に見せたりしないこと。
